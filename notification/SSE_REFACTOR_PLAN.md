전면 재수정 

현 알림 SSE 문제점
: netty 비동기 채택이 아무 의미가 없어짐
: 비동기 + 동기 PINg 방식
: 목표치 달성전 여러 스케일 구조를 고려 

결과
: 최소 성능, 최소 리소스 로 최대 SSE 연결 달성이 수정할 수록 멀어짐 

해결 방안
: 
UDP 사용하여 일방적인 전달 하는 SSE-stream 하는게 좋아보여
Session-ID(브라우저) 를 redis에서 저장하고 member_id와 매칭하고 전달하는 방식으로 일방 통행 방식을 채택하고

수신 받는 쪽에서도 수정이 필요하겠지

메시징 기법을 사용하자 [`수신 역할 = 연결이 되었는지`] 를 가정한다면 실시간으로 체크할 필요성보단
부하 테스트 최소 3분~15분이라 가정하에 1분 동안 수신 자 쪽에서 연결 [성공/데이터유실/실패 를 가지고 있는다]
- 성공 : Ping count + 1 
- 데이터 유실 :
  - 유실시 대처 방안? -> 알림함에 다이렉트 로 보여주자 
  - 화면 갱신하여 알림함 최신화 (k6에서는 제외됨)
- 실패 : ping count 변화 없음

sse_messaging_ping_result =
{
    "총전송받은횟수":{number},
    "성공적으로받은횟수":{number},
    "시간들" :{
        "date":{localDateTime},
        "전송상태":{성공/유실/실패}
    }
}

- 프로메테우스에 성공 우뮤가 적재 될수있도록 한다.
